# Mac用ローカルランチャー（Chrome版）

ローカル起動画面のボタンから、新規のGemini Webチャットへ魔法の長文指示を入力・送信する試作です。Gemini API、APIキー、Gem、スキルは使用しません。Gemini側で画像生成を利用できるアカウントとインターネット接続が必要です。

## 起動

Node.js 20以上があるMacで、プロジェクト直下の `Start Crystal Quest.command` をダブルクリックします。または、このフォルダで `npm run local` を実行し、Chromeで `http://127.0.0.1:4174/` を開きます。

初回は起動画面の説明に従い、`chrome://extensions` から生成された `.local/crystal-quest-extension` フォルダを読み込んでください。Chromeの確認画面でアクセス先を確認してください。拡張機能を追加後、ローカル画面を再読み込みします。

1. ChromeのGeminiにログインしておきます。
2. ローカル画面で魔法を選び、開始ボタンを押します。
3. 拡張機能が新規のGeminiタブを開き、全文の入力を確認して送信を一度だけ行います。
4. 指定の歓迎文が表示されたら、Geminiの「＋」から写真を選んで送信してください。

停止は起動したターミナルでCtrl+Cです。再起動後もChrome拡張は登録済みのままです。不要になったら `chrome://extensions` で「Crystal Quest Local」を削除できます。常駐・自動ログイン・バックグラウンド起動の登録は行いません。

## 権限とデータ

- `scripting` と `https://gemini.google.com/*`：このランチャーが作成したGeminiタブで入力欄・送信ボタン・初回返答を確認するために使います。既存タブや別のサイトの会話を収集する処理はありません。権限自体はGeminiサイトへのアクセスを許可するため、コードは読み込み前に確認できます。
- `storage`：進行状態とリクエストIDをブラウザセッション中だけ保持します。Cookie・パスワード・写真・会話本文を保存する処理はありません。
- ローカル画面のブリッジ：`http://127.0.0.1:4174/` の最上位ページだけから、既知の魔法IDを受け付けます。公開サイト、別ポート、iframe、任意のURLや任意コードは受け付けません。
- サーバー：127.0.0.1だけで待ち受け、HostとOriginを照合し、決められた静的ファイルだけを配信します。外部サービスへの通信はGeminiの通常のWeb操作だけです。

## 中断した場合

Geminiは新規タブにも下書きを復元することがあります。下書きが今回の魔法の指示全文と一致する場合だけ、そのまま使用します。別の文章や別の魔法が入っていたら上書き・送信せず停止します。入力照合では、リッチテキスト編集による空行数の変化を許容し、それ以外の文章の違いを検知します。

開始リクエストIDの再利用で同じ指示を再送しません。別の処理が進行中なら新規開始を拒否します。送信直前に記録を残すため、ブラウザや拡張機能が中断した後は、自動再開・自動再送せず「確認が必要」と表示します。Gemini側を確認してから新規開始してください。

プロンプトの送信だけで成功にせず、Geminiのユーザーメッセージと指定の歓迎文を確認して「準備完了」とします。Geminiの画面変更、ログイン切れ、応答遅延、異なる返答では停止する場合があります。モデルの生成内容や写真受信後の画像枚数はランチャーによって強制できません。

この試作はChromeのWeb版向けです。Safari、スマートフォンのGeminiネイティブアプリ、公開サイトから追加設定なしで起動する方式には対応していません。通常の `npm start` および公開サイトの手動導線は変更していません。

## 開発

`local/extension/` が拡張機能のソース、`local/web/` が起動画面です。`npm run local:prepare` または `npm run local` が正規の `dist/quest.js` と拡張ソースを `.local/crystal-quest-extension/` にコピーします。ソース変更後は準備コマンドを再実行し、Chrome側で拡張機能を再読み込みしてください。依存パッケージは不要です。

`npm run check` は既存プロンプト、URL生成、ローカルの境界と重複抑止のテストです。Geminiの実画面検証は別途必要で、ユニットテストの成功だけを実際の送信・画像生成成功とは扱いません。

## 実機検証の結果

2026年11月12日、MacのChromeに作成した拡張機能を追加し、ローカル画面からアルテマの新規チャットを開く・指示を送信する・指定の歓迎文だけが表示される・ローカル画面が完了状態になるところまで確認しました。初回の入力で空行表現の違いを検知して停止したため修正し、同じ指示の下書き復元にも対応しています。

写真を送信した後の画像生成は未検証です。実機で試した魔法はアルテマのみです。6種類すべてのプロンプト生成は自動テストで確認しています。
